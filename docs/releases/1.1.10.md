Live MIDI input: play an instrument from a MIDI keyboard and record the performance as MIDI
clips. Project-file schema **24** (additive; older projects open unchanged with no MIDI input
assigned). ASIO, BPM transfer (1.1.4), export fixes (1.1.5), insert persistence / header column
(1.1.7), level meters (1.1.8), the mute rule and the Inspector meter (1.1.9) untouched. Full
report: `docs/LIVE_MIDI_RECORDING_2026-10-03.md`.

## Added

- **MIDI Input / Input Channel** in the Inspector for instrument tracks and MIDI tracks: None,
  a specific device, or All MIDI inputs; channel filter All / 1–16 (a filter — recorded events
  keep the channel they arrived on; the track's MIDI Channel (Preserve / Force) decides what the
  instrument hears, as for playback). Saved in the project by device identity and name; a device
  that is not connected shows as "(missing)" and stays assigned.
- **Monitor (speaker) on instrument and MIDI tracks**: hear the instrument live, transport
  stopped or playing. Routed MIDI tracks (e.g. Organ Lower / Pedal) play through their `MIDI To`
  instrument on their own channels. Monitor never changes the project.
- **Record-arm (R) on instrument and MIDI tracks**: with Record, every armed track with a MIDI
  input records one clip per take — several MIDI tracks at once, and together with the armed audio
  track. One boundary for all of them (the count-in end), one undo step for the whole take.
  Notes, velocity, channel, CC (incl. CC1 / 7 / 11 / 64) and 14-bit pitch bend are recorded; keys
  held across the start enter at the start, keys held at Stop end at Stop, a held sustain pedal is
  released at Stop; nothing is quantised or interpolated; an empty take leaves nothing behind.
- **Pitch bend** in MIDI clips: recorded, saved, played back (realtime, offline export, proxies)
  and exported as Pitch Wheel events.
- A green dot on the track header while MIDI arrives; a growing red REC region on the lane during
  a take; an Inspector status line when the device is missing, the destination has no playable
  instrument, the Secondary is used temporarily for monitoring, or input overflowed.
- Diagnostics: `--stability-live-midi <project>`, `LiveMidiRecordingFocusedTests`.

## Changed

- An audio take committed from the Record / Stop flow is now part of an undo step (together with
  any MIDI clips of the same take).
- Instrument tracks whose Primary is missing but whose current proxy plays: while Monitor is on
  and a Secondary is configured, the Secondary plays the existing clips and the live input
  temporarily (the proxy and a live instrument never play the same part at once); Monitor off
  returns to the proxy. The proxy stays valid.
- Recording with Cycle on and an armed MIDI track is refused with a message (turn Cycle off);
  Cycle itself is never changed. Audio-only cycle recording is unchanged.

## Not included (documented limitations)

- Aftertouch / channel pressure are heard but not recorded; program change is dropped; SysEx /
  MPE unsupported. No MIDI loop recording, no punch-in, no PDC, no pitch-bend editor lane.
- Verified with injected device-style MIDI and the physical RME MIDI port opened and routed; an
  audible test with a keyboard remains with the user.

## Known, unchanged

- AmpliTube 4 teardown crash (`0x7675E`) remains intermittent at shutdown / project reload.
