`docs/PERF_PROFILE_100TRACKS_2026-10-06.md`.

## Changed

- **Live instruments render in parallel.** The audio callback now hands each live instrument's
  generation stage (its MIDI for the block + the plug-in's `processBlock`, into the instrument's
  own buffer) to a fixed pool of realtime worker threads and joins them before the mix. Inserts,
  fader / mute / pan, meters, routing, sends and the summing order are unchanged and still run on
  the callback thread in row order, so the mix is the same as before (bit-identical for
  deterministic instruments). MIDI timing, transport, cycle, monitoring, recording, proxy
  selection (proxy-backed rows stay on the callback thread), offline export and proxy rendering
  behave as before. No added latency.
- **Measured on the 100-track load-test project** (Release, ASIO Fireface USB 48 kHz / 512,
  same build): callback mean 9.9 ms → 2.1 ms, worst block 16.5 → 3.3 ms, budget overruns 836 → 0
  in 45 s, playback in real time. The original project (3 instruments) goes 0.88 → 0.49 ms.
- Worker count: a conservative machine default (half the physical cores minus one, at most 7,
  none on ≤ 3-core machines). Diagnostic override: start DAL with `--instrument-workers N`
  (0 = the previous serial behaviour, same code). Small workloads run serially automatically.
- Worker threads join MMCSS "Pro Audio" (thread priority only; the process priority is not
  changed).
- The opt-in profiler reports instrument time as summed CPU across threads plus the callback's
  wall time for the parallel section and its idle wait; `--stability-perf-profile … --generation
  ab` compares serial and parallel in one run.

## Verified

- `InstrumentParallelFocusedTests` (new): serial vs parallel bit-identical output on the
  production engine with real hosts and a deterministic instrument; one `processBlock` per
  instance per block, never concurrent; Off / muted rows; Group + send; small-workload fallback;
  0-worker override; offline mixdown parity; 52 plug-in swaps + a device stop / start under a
  running device thread without any overlap of processing with destruction or re-prepare.
- Release scenarios with the parallel default on temp copies: `--stability-midi-routing`
  (several MIDI sources into one instrument, offline parity), `--stability-live-midi` (fixture:
  monitoring, recorded take, device loss, export), `--stability-smoke` (reload, delete / undo
  with playback, open / save / close), `--stability-mixdown`; `ExportLevelFocusedTests` 47 checks.

## Known

- Closing DAL with the 100-track project loaded still ends in the known AmpliTube 4 teardown
  crash (`AmpliTube 4.vpa+0x7675E`) — reproduced identically with the serial override; unrelated
  to this change.
- The RME driver fixes the buffer size in its own panel; 1024 was not measurable from DAL.
- No listening verification was done for this release; the figures are engine measurements.
