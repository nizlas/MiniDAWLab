Diagnostics release following up the pre-gain report on the user's own project. No audio
behaviour changes; project-file schema unchanged (23).

## Investigation result

- The −24 dB pre-gain edit made through the Inspector **was committed, on the right track**, in
  the user's live session (visible in its autosaves). The chain displayed value → committed value
  → published snapshot → realtime render is intact; measured again on a copy of the user's project
  through the real Inspector key path: level entering the first insert scales by 0.062 (expected
  0.063) while playing.
- The AmpliTube track in that session is **muted**, so it renders nothing — no pre-gain value can
  be heard from it. Unmuted, the user's AmpliTube preset turns a −24 dB input change into a
  ≈ −5 dB output change. Details: `docs/PREGAIN_EXPORT_VERIFICATION_2026-09-30.md` §3b.

## Added (diagnostics only)

- `PluginInsertHost` insert level tap: peak/RMS of one track's signal before its first insert and
  after its last insert, relaxed atomics, off by default.
- `--stability-pregain-inspector <project>`: activates the AmpliTube track like a header click,
  types 0 → −24 dB into the real Inspector field (TextEditor key path + Return), compares
  displayed/committed value and track id, and measures the insert chain while playing — with the
  project's own mute state, then unmuted.
