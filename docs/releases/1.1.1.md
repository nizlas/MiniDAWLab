# Danielssons Audio Lab 1.1.1

| | |
|---|---|

| Portable | `DanielssonsAudioLab-1.1.1.zip` |

Bug-fix release: MIDI tracks now do everything instrument tracks do with MIDI
clips. Project-file schema is unchanged (23).

## Fixed

- **MIDI file import onto MIDI tracks** — "Import MIDI file..." accepted only
  instrument rows and answered "That track is not an instrument lane" on a
  plain MIDI track, even though both kinds store clips in the same controller.
  Import now accepts every row that owns timeline MIDI clips.
- **Moving MIDI clips between MIDI and instrument tracks** — the arrangement
  drag only treated instrument lanes as drop targets, and the move itself
  required both ends to be instrument rows, so clips could not be dragged from
  an instrument track to a MIDI track or back. Both directions now work, in
  one undoable step, with the clip's notes and CC data carried along.
- **Copy, paste and delete of MIDI clips on MIDI tracks** — the same
  instrument-only restriction blocked the clipboard shortcuts on MIDI rows.

MIDI tracks still differ from instrument tracks in the one way they should: a
MIDI track has no instrument of its own and plays through the instrument row
picked under "MIDI To" in the Inspector. A MIDI track with no destination is
silent but fully editable, as before.

## Verification

A new bounded scenario, `--stability-midi-track-parity`, runs the production
paths: it writes a Standard MIDI File from a MIDI row's clip, imports it back
onto that MIDI row through the real parse-and-append path, moves the imported
clip to an instrument row and back through the real cross-track move, then
saves, reloads and asserts the notes are intact. It fails on the pre-fix code
("move MIDI row -> instrument row was refused"). The existing
`--stability-midi-routing` scenario still passes, so MIDI delivery to a
destination instrument and the v18 round-trip are unchanged.

The file-chooser click and the mouse drag themselves remain manual checks.
