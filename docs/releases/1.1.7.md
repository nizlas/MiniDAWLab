Two user-reported problems: VST3 inserts that did not come back after saving the project, and a
track-header column too narrow for the Monitor button. Project-file schema unchanged (23); ASIO,
BPM transfer to VST3 inserts (1.1.4) and the export fixes (1.1.5) are untouched. Full report:
`docs/INSERT_PERSISTENCE_HEADER_COLUMN_2026-10-01.md`.

## Fixed

- **Inserts on instrument, group and master rows are now saved and restored.** Until now only
  audio rows' insert chains were written to the project file (and instrument rows were skipped on
  load), so a DAL Mono Delay added as a Post insert on an instrument track — or any plug-in on a
  group/master bus — vanished on the next save + reopen. All three save paths (Save, Save As,
  autosave) and the loader now cover every row kind. Identity + locate path, full plug-in state
  (editor edits included), Pre/Post placement, chain order and separate state per instance survive.
- **A temporarily unavailable plug-in no longer loses its configuration.** A saved insert whose
  plug-in cannot be instantiated (bundle missing, scan/instantiation failure, or a *different*
  plug-in at the saved path) stays in its chain position as `"<name> (unavailable)"`, silent in the
  audio path; saving again re-emits its identity and state byte-for-byte, and the state is applied
  once the plug-in is back. A saved state is never applied to a plug-in of another identity.
  Explicit removal is still respected: a removed insert is gone from the next save and never
  resurrects.
- **Track-header column: one shared, draggable width.** Default **144 px**, minimum **132 px**
  (widest button row — [Instrument][Power][Mute][Monitor][Arm] — fully inside the header with the
  standard 8 px pad; the old fixed 120 px clipped Arm), maximum 480 px; logical (DPI-independent)
  px. A drag handle on the header/timeline boundary (resize cursor) widens the column for long
  names; headers, lanes, grid, ruler, playhead and hit-testing all move together; musical clip
  positions are unchanged. Names are fitted/truncated and never change the width.
- **The column width is remembered app-wide** (`%APPDATA%\MiniDAWLab\ui-layout.xml`, written
  once per completed drag), restored at the next start, clamped on narrow windows (at least 160 px
  of lane area stays visible), unaffected by adding/removing tracks, no undo step.

## Added (tests / diagnostics)

- `InsertPersistenceFocusedTests` (121 checks): real DAL Mono Delay + BassEvening through the
  production save/load entry points on audio / instrument / group / master rows; echo time and mix
  verified in audio after reload; unavailable placeholder, identity mismatch, removal, placeholder move.
- `TrackHeaderColumnFocusedTests` (103 checks): header geometry + offscreen paint per row kind at
  120 (negative control) / 132 / 144 / 240 px, long names, clamp formula, `ui-layout.xml` round trip.
- `MiniDAWLab.exe --stability-inserts <project>` and `--stability-header-column <project>`: the
  same checks inside the real app (ProjectIoCoordinator Save/reload/autosave-recovery; every
  header/lane/ruler/overlay on one boundary with PNG evidence).

## Known, unchanged

- AmpliTube 4 (`AmpliTube 4.vpa` offset `0x7675E`) can crash while its instance is destroyed —
  at app shutdown or when a project containing it is reloaded. Pre-existing and intermittent
  (reproduced today with the unmodified 1.1.6 Debug build; the user's own session hit it at
  20:06:35 on close); not caused by this release. Still an open stability-audit item.
