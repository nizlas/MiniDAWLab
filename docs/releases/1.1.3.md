# Danielssons Audio Lab 1.1.3

| | |
|---|---|
| Version | 1.1.3 |
| Date | 2026-09-26 |
| Installer | `DanielssonsAudioLab-1.1.3-Setup.exe` |
| Portable | `DanielssonsAudioLab-1.1.3.zip` |

Stability release: fixes a MIDI-clip paste/move crash and a paste side effect,
plus a stale internal check surfaced by the audit. Project-file schema is
unchanged (23).

## Fixed

- **Crash when moving a MIDI clip whose editor was open (use-after-free)** — a
  cross-track move (and delete) frees the clip object, but the MIDI editor kept
  a raw pointer to it and dereferenced it on the controller's next change
  callback. The editor is now detached synchronously the moment its bound clip
  is removed or moved, before any later callback can run, and the drum-name row
  refresh re-resolves the clip by id as a second safeguard. Confirmed with
  AddressSanitizer: the pre-fix build reports a heap-use-after-free right after
  the move; the fixed build is clean.
- **Paste no longer opens the MIDI editor** — Ctrl+V created the clip and also
  opened its editor, which both surprised and set up the crash above. Paste now
  only creates and selects the clip; double-click still opens the editor.
- **MIDI editor on a MIDI track no longer trips an internal stability check** —
  a check predating MIDI-track editing flagged an editor open on a `Midi` row
  as invalid; it now validates the row's routed destination instead.

## Audit notes

- The reported "all sound stops after MIDI import" could not be reproduced
  through the production import path: an independent audio-health probe shows
  every instrument still rendering and the device output non-silent after
  importing onto a new MIDI track, stopped and playing. The most likely cause
  was the use-after-free above corrupting state before the visible crash;
  removing it removes that path. Recorded/imported audio, transport and the
  audio callback stay healthy across the full create → import → copy/paste →
  move → play sequence.
- Repeated project load/unload of some third-party plug-ins (e.g. AmpliTube)
  can still crash inside the plug-in's own code; DAL captures those crash
  reports under `%APPDATA%\MiniDAWLab\crash-dumps\`. This is not a DAL defect
  and is out of scope for this release.

## Known limits

- Recording still captures one armed audio track at a time.
- Capacity for a 10-minute, 150-track project has not been measured.
- Full plugin delay compensation, a low-latency tracking mode and calibrated
  recording-latency compensation remain future work.
- Autosave runs every 60 seconds when the project has unsaved changes; it is a
  safety net, not a substitute for saving (Ctrl+S).
