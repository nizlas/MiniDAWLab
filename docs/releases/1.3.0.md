Audio-row strips and instrument strips now run in the existing render pool, and an experimental
read-ahead path can pre-render eligible audio rows. Project format stays **v28**.

## New

- **Parallel audio and instrument strips.** Eligible audio-row strips and instrument strips
  (generation and strip together) are jobs in the render pool that 1.2.1 already used for
  instrument generation. The callback joins that work instead of processing those strips
  serially. Reports: `docs/PARALLEL_A1A2_LOCAL_VERIFICATION_2026-10-09.md`,
  `docs/PARALLEL_A1A2_48_SAMPLES_2026-10-09.md`.
- **Experimental read-ahead, off by default.** Nothing is pre-rendered unless the process is
  started with `--experimental-readahead` (depth 3) or `--experimental-readahead=N` (N from 2
  to 8). There is no new setting and no change to the default. Without the flag the engine
  builds no read-ahead objects. At most 16 audio rows are adopted; monitored, record-armed and
  recording rows stay on the direct path. Report: `docs/READAHEAD_PROTOTYPE.md`,
  `docs/READAHEAD_PROTOTYPE_LOCAL_VERIFICATION_2026-10-09.md`.

## Measured on the test machine

One computer, one 100-track project (36 audio rows unmuted, 48 instruments, ASIO Fireface USB,
48 kHz, Cubase closed, one DAL). These figures are that run's results. They are not a
performance promise for another machine, buffer size or project.

- **Parallel strips, flag off, actual buffer 512** (candidate `10374e2` against 1.2.1, bars
  17–30): callback mean / max **2.30 / 4.77 ms** (1.2.1 was 5.64 / 9.34 ms). Deadline overruns
  0 (1.2.1 also 0); blocks over 70% of the budget 0 (1.2.1 had 292). At the cycle wrap the same
  candidate still missed one deadline (max 13.1 ms); 1.2.1 missed three (max 38.5 ms).
- **Same parallel build, actual buffer 48:** the passage mostly kept up (mean about 44–46% of
  the 1 ms budget) with a few isolated blocks over the budget. The cycle wrap was an audible
  dropout on this project (callback about 11.6 ms).
- **Read-ahead on, actual buffer 512, after the adoption fix** (`--experimental-readahead`,
  counters from the first Play): the 19 s passage and the cycle wrap both finished with
  **0 missed segments and 0 abandons**. Passage callback mean / max 2.107 / 3.850 ms; wrap
  1.847 / 9.312 ms, no deadline overrun.

## Known

- Read-ahead does not run unless the flag above is passed.
- **AmpliTube 4** still crashes intermittently while its instance is destroyed, including at
  application exit (`AmpliTube 4.vpa`, offset `0x7675E`, phase "app shutdown begin"). Dumps
  that match that module, offset and phase do not by themselves establish the cause or rule
  out another thread. Seen with and without read-ahead, after playback had already finished.
  Save before switching projects.
- The cycle-wrap insert spike above is still present. At 48 samples on this project it does
  not fit in one buffer.
- AmpliTube "Param 1" did not round-trip in the save check, including on the direct path.
  A DAL Mono Delay row did restore its parameters and a 250 ms delay. That plug-in is not
  part of this installer.
