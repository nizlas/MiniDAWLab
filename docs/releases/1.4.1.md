# Danielssons Audio Lab 1.4.1

| | |
|---|---|
| Version | 1.4.1 |
| Date | 2026-11-06 |
| Installer | `DanielssonsAudioLab-1.4.1-Setup.exe` |
| Portable | `DanielssonsAudioLab-1.4.1.zip` |

Large projects use less CPU and memory, and AmpliTube 4 can no longer take DAL down when its
instances are closed. Project format stays **v32**; projects open in 1.4.0 and 1.4.1 alike.

## New

- **Off unloads plug-ins.** Switching a track Off unloads its effects and instrument and frees
  their memory and CPU. A track saved Off loads no plug-in when the project opens. Switching it
  On loads them again, one at a time, with their settings, before the track plays. Power changes
  only while the transport is stopped, and Undo / Redo that would switch a track On or Off waits
  for Stop as well.
- **AmpliTube 4 runs in its own shared process.** All AmpliTube 4 instances run in one helper
  process next to DAL, with the same timing as before (no added latency). If that process
  crashes or stops responding, DAL keeps running: the AmpliTube inserts go silent, and DAL
  restores them after Stop ("Restoring plugins..."), or asks before restarting a host that
  stopped responding. Closing a project, quitting DAL, or switching the last AmpliTube track
  Off ends the helper without running AmpliTube's own shutdown code, which was the source of
  the known crash.
- **Automatic proxy rendering is opt-in.** A track renders a proxy only when you choose it.
  Projects that never chose a mode now read as Manual.
- **Automatic rest.** Effects that declare themselves audio processors (EQ, dynamics, reverb,
  delay, distortion and similar) stop processing while they only receive silence, and wake on
  input, on a parameter or preset change, and on Play and Stop. This lowers CPU. It does not free
  plug-in memory. Instruments and generators never rest.

## Known

- Decoded audio of tracks that are Off stays in memory for now (about 80 MB in a large test
  project). Only plug-in memory is freed by Off.
- AmpliTube 4's own editor works and opens as its own window. The generic parameter panel
  shows nothing for AmpliTube 4 yet.
- If the AmpliTube helper crashes, changes made in AmpliTube since its last saved state can be
  lost; the restore message names the affected inserts. Saving the project captures the
  current state.
- With many AmpliTube 4 tracks playing at once, each block costs slightly more than before
  (about 0.06 ms per AmpliTube track per block on the test machine).
- Read-ahead still starts or stops only at the next launch.
