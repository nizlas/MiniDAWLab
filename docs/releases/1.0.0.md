First 1.0 release. This is a packaging milestone for functionality already
delivered and manually exercised; the project-file schema is unchanged
(version 22, same as 0.9.x-era builds with pre-gain).

## What's included

- **Audio recording, editing and mixing** — multi-track recording with
  count-in and cycle takes, clip editing on the arrangement, per-track fader,
  pan, mute/off, sends, group/master routing, insert effects (Pre/Post), and
  offline mixdown (WAV/MP3).
- **MIDI editing, instrument hosting and routing** — piano-roll and drum
  editing, CC automation lanes, per-track MIDI channel handling, MIDI export,
  VST3 instrument hosting, and MIDI tracks routed to instrument tracks
  ("MIDI To").
- **ASIO support** — native ASIO device backend on Windows for low-latency
  interfaces, alongside the existing Windows Audio/DirectSound backends.
- **Portable project folders** — projects are self-contained folders with
  project-relative audio references, so a project can be moved or copied as a
  unit.
- **Instrument proxies and explicit Secondary fallback** — a track's
  instrument can render through a lightweight proxy, with an explicitly
  chosen Secondary instrument as fallback when the Primary is unavailable
  (with a clear failure reason and retry).
- **Audio-track pre-gain** — per-audio-track input trim (−24 to +24 dB)
  applied before the track's inserts and fader; nondestructive (source files
  and recorded takes are unchanged).

## Known limits

- Capacity for a 10-minute, 150-track project has **not yet been measured**;
  no performance certification is claimed for that scale.
- Verification on Behringer hardware is still pending.
- Full plugin delay compensation, a dedicated low-latency tracking mode,
  anticipative processing, and verified/calibrated recording-latency
  compensation remain future work.
- Round-trip latency has not been measured; no universal third-party plugin
  compatibility is claimed (plugins can crash in their own code — crash
  reports are captured under `%APPDATA%\MiniDAWLab\crash-dumps\`).
- No software input monitoring: monitor recorded sources through the
  interface's direct monitoring.
- Autosave runs every 60 seconds when the project has unsaved changes; it is
  a safety net, not a substitute for saving (Ctrl+S).
