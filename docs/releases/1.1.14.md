Proxy rendering: the isolated instrument is verified ready before a proxy is rendered, a silent
render of non-empty content is never published, and publication never mistakes a different file for
the same proxy. Report: `docs/PROXY_RENDER_READINESS_2026-10-05.md`; architecture:
`docs/CURRENT_ARCHITECTURE.md` "Proxy render readiness + publication identity"; steering:
`docs/PORTABLE_INSTRUMENTS_AND_PROXIES.md` §14.2 (step 4b, step 8), §16.1, §16.3.

## Root cause of the 1.1.13 observation

The same render identity gave a 49.3 s proxy in Debug and a 39.0 s proxy in Release. Measured on
copies with frozen inputs: Groove Agent SE restores its state synchronously but loads its kit
samples asynchronously; the render started right after `prepareToPlay`, so the Release build
(600–900× realtime) rendered **39 s of digital silence** and the Debug build rendered the first 6–12 s
of notes silent. Format / length validation accepted the silent asset and it was published as
Current. The length difference was the symptom: a real 11.3 s cymbal decay versus the 1 s silence
window on a silent instrument. The user's saved TSE project still references such a silent Groove
Agent generation from 2026-09-15 (read-only finding; see the report §6).

## Changed behaviour

- **Readiness verification before every proxy render.** The content's own notes are played into
  the prepared render instance until its response has settled (passes 250 ms apart; bounded 20 s /
  60 s); the render starts on an instrument that can sound its content. Groove Agent SE: verified
  after ~1.2–1.8 s; the proxy is complete from its first note in Debug and Release alike, and
  byte-identical between the builds. Instruments that answer at once add well under a second.
- **No silent "Current" proxy.** A render whose scheduled notes produced nothing above the tail
  threshold fails with `NoAudibleOutput`; the previous generation and metadata are retained, the
  status shows the failure, Retry is available. The explicit silent generation remains reserved for
  empty destinations.
- **Publication identity.** An existing file under a generation name is reused only when its bytes
  are identical to the new render. Anything else under that name — an earlier incomplete render, a
  legitimately different render of a non-deterministic instrument, a foreign file or directory — is
  left untouched and the new proxy is published under a sibling name
  (`track_<id>_<fingerprint>_<n>.wav`); the project metadata always names the file in use. The
  "generation-name collision" failure no longer occurs; nothing is ever overwritten or deleted.
- Diagnostics: `--stability-proxy-render-probe <project copy> <trackId> <outDir> …` renders one
  destination repeatedly through the production pipeline with kept artifacts and a content analysis.

## Known, unchanged or observed

- **VB3-II (TSE preset) still cannot be proxied**: after any note it parks −4.4 dBFS of DC on its
  output (organ-dc defect), so the tail detector never sees silence and the render fails honestly
  at the 30 s cap (`TailLimitReached`) — with and without readiness, with and without the offline
  indication. Nothing is published; the Primary plays live.
- Repeated re-renders of one identity may legitimately differ (round-robin / sample-level
  variation) and then accumulate sibling files; they are listed by the existing unreferenced-
  generation report and never deleted automatically.
- Already-published silent generations from earlier versions are not detected at load; re-render
  the destination on a machine with the Primary (proposed follow-up: a load-time plausibility
  audit).
- One intermittent 1.1.13 cycle-takes failure was observed (combined past-end take: MIDI one device
  block shorter than audio; passed on rerun) — recorded for follow-up, not touched here.
- AmpliTube 4 teardown crash (`AmpliTube 4.vpa+0x7675E`) remains intermittent at shutdown.
